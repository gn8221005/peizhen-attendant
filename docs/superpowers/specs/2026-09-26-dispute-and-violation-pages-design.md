# 争议处理与违约记录页面设计

日期：2026-09-26
状态：待审阅

## 目标

按照 `design-page/` 中新增的争议处理与违约记录原型，为陪诊师端补齐可操作的原生页面。覆盖争议列表、争议详情、说明提交和违约记录，并支持查看不同处理状态以及从待回应流转到平台处理中。

界面继续使用 UniApp/Vue 原生布局、项目现有导航和页面风格。PNG 原型只用于视觉参考，不作为页面背景或包含控件文字的运行时截图。证据区域由原生控件与本机选择的图片预览组成。

## 现状与约束

- 当前应用注册了 14 个页面，争议和违约记录尚无运行时路由。
- `design-page/` 已提供争议列表、待回应、处理中、提交说明、投诉成立、投诉不成立和违约记录原型。
- 项目现有相关数据使用静态原型数据，登录和认证状态通过 UniApp 本地存储演示；本次没有发现争议或违约记录服务接口。
- 本次增加本机演示数据与状态保存，不接入后端，不执行真实上传，也不改变已有服务订单路由约定。
- 页面按现有系统字体、间距和卡片风格实现，适配 H5 与微信小程序安全区和滚动区域。

## 页面与路由

| 路由 | 页面职责 |
| --- | --- |
| `pages/disputes/index` | 争议列表及全部、待回应、处理中、成立、不成立筛选；记录卡展示类型、订单号、投诉时间和状态。 |
| `pages/dispute-detail/index` | 按记录 ID 展示订单、用户投诉、双方说明/凭证及状态内容。待回应状态展示截止时间与说明入口；处理中状态展示审核时间线；成立和不成立状态展示平台处理结果。 |
| `pages/dispute-response/index` | 提交陪诊师说明，包括必选回应类型、最多 500 字的情况说明，以及最多 9 张本机图片预览。 |
| `pages/violation-records/index` | 展示违约类型、关联订单编号、处理时间；点选记录后展开处理摘要。 |

个人中心服务中心加入“争议处理”和“违约记录”入口，原 4 项入口调整为可换行的 3 列网格。助手预览页面增加以上路由的入口，便于查看各状态示例。所有新增页面使用 `AppTopNav` 并提供合理的返回落点。

## 数据、状态与交互

- 在 `data/` 中定义争议和违约记录类型及初始示例，至少提供待回应、处理中、投诉成立和投诉不成立四种争议状态，以及原型中的爽约、迟到、服务态度问题和提前结束服务等违约类型。
- 通过新增的争议记录 composable 读取和写入 UniApp 本地存储；存储损坏或读取失败时回退到初始示例数据。不同页面共用同一份记录状态。
- 争议列表的五个筛选项按当前记录状态过滤。卡片打开对应 ID 的详情页；无匹配记录时显示与现有页面一致的原生空状态。
- 待回应详情进入提交说明页。说明页校验回应类型与非空说明，限制 500 字和最多 9 张图片。本机图片通过 UniApp 选择能力生成本地预览，不向服务端传输。
- 提交成功后更新该条记录的回应内容、提交时间、图片路径和状态为“处理中”，写入本地存储并返回争议详情；详情与列表立即反映最新状态。
- 处理中详情用时间线标出用户投诉、陪诊师回应及平台审核。成立详情呈现违约类型、信誉处理、订单资金处理、陪诊师收益处理、接单限制、处理时间和平台说明；不成立详情呈现处理时间与平台结论。
- 违约记录卡展开该记录的处理摘要，避免增加原型未提供的独立详情路由。
- 无效记录 ID 返回争议列表或显示空态；取消图片选择不改变页面状态；超过图片数量时提示上限。

## 组件与文件边界

- 新增四个独立页面，分别负责列表、详情、回应表单和违约记录展示。
- 使用独立 typed data 模块保存静态示例；composable 负责本地读取、持久化和回应提交，页面通过明确的方法共享记录状态。
- 可在新增页面内部建立轻量卡片/状态展示组件；不引入通用页面渲染器，不重构无关的服务订单数据结构。
- 个人中心仅调整入口网格与两个路由映射；助手页仅增加预览项。
- 本次不额外生成栅格照片素材。顶部状态图标和凭证占位使用 CSS/原生布局绘制；实际证据缩略图由用户在本机选择预览。

## 错误与边界状态

- 本地存储不可用时，使用默认示例数据继续渲染；尝试保存失败时保留当前页面状态并提示“保存失败，请重试”。
- 表单缺少回应类型或说明时显示对应提示，不修改争议状态。
- 图片选择取消为无操作；图片总数达到 9 张时显示上限提示。
- 页面内容区支持滚动，固定提交栏为底部安全区留白；长订单号、说明和平台处理文本可换行。
- 争议数据为演示数据，不代表真实处理结论或实际违约处罚。

## 完成标准

1. `pages.json` 注册四个新增路由，个人中心和助手预览均可到达列表与违约记录。
2. 五个列表筛选显示相应状态记录；四种争议状态展示对应详情内容。
3. 提交说明包含必填校验、字符计数和本地图片预览；提交后争议变为处理中，并能在列表与详情页看到相同状态。
4. 违约记录列表展示规定字段，点选可展开处理摘要。
5. 所有新增界面由原生 Vue/UniApp 组件构成，不使用整页原型图；页面安全区和长文本布局遵循现有工程约定。
6. 本次不增加自动化测试或运行测试命令；交付说明如实列明未执行的验证项。

## 自检

- 路由数量为 4，职责对应已有原型，没有为成立/不成立状态复制独立详情页。
- 数据流明确从静态示例初始化，经 composable 读写本机状态；表单提交后的状态变化对列表和详情共享。
- 本地图片预览与真实上传分开描述，数据不会发往服务端。
- 无效 ID、存储失败、空筛选、取消选图和超出 9 张限制均有定义。
- 完成标准没有要求增加或运行自动化测试；既有路由与订单数据结构维持不变。
